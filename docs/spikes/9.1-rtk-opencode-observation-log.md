# Spike 9.1 — RTK on OpenCode

Observed 2026-08-06 on Windows 11 (26200), no WSL. The question was narrow: RTK ships
`rtk init --opencode`, and the manifest in `providers/rtk.ts` declared Claude Code as RTK's only
harness. One of the two was wrong.

## What was run

| Component | Version |
| --- | --- |
| rtk | 0.44.0 (winget `rtk-ai.rtk`) |
| OpenCode CLI | 1.18.11 (`AppData/Roaming/npm/opencode`) |
| OpenCode Desktop | 1.18.14 (Electron 42.3.3, `AppData/Local/Programs/OpenCode`) |

## The installer

`rtk init --opencode` refuses a project-local install — `rtk: OpenCode plugin is global-only. Use:
rtk init -g --opencode`. The global form writes exactly one file:

```
C:\Users\<user>\.config\opencode\plugins\rtk.ts
```

It does **not** edit `opencode.jsonc`; the file before and after the install is byte-identical. This
matters for detection: RTK's integration is a plugin *file*, never a `plugin` array entry, so an
adapter that reads only the `plugin` array cannot see it. HarnessTrim installs the same way, into
`.opencode/plugin/`.

The plugin delegates to `rtk rewrite <command>` on `tool.execute.before`, filtered to
`tool === "bash" || tool === "shell"`. `rtk rewrite "git status"` returns `rtk git status`;
`rewrite` is a documented subcommand ("single source of truth for hooks").

## Both plugin directory spellings load

Probe plugins that append to a file on load were placed in `.config/opencode/plugin/` (singular) and
`.config/opencode/plugins/` (plural), and one `opencode run` loaded both. The upstream documentation
names the plural; the binary carries both strings. RTK's choice of `plugins/` is correct, and the
singular that HarnessTrim uses is not stale.

Plugins load **per session**, not at server boot: `opencode serve` alone fired no probe, and creating
a session through `POST /session` fired it immediately. A Desktop launch that opens no session
therefore proves nothing either way.

## OpenCode CLI — intercepted

`opencode run` against a scratch repository, prompted to run `git status`:

```
$ rtk git status
* No commits yet on master
A  file.txt
```

The transcript shows the rewritten command, the output is RTK's compact form, and
`rtk gain --all --format json` moved `total_commands` 5614 → 5616 across the two bash calls. The same
run through `opencode serve` + `opencode run --attach --session` moved it 5623 → 5635 and also
rewrote `ls -la` to `rtk ls -la`.

The surface is `tool.execute.before`, which the harness manifest did not declare — it listed
`tool.execute.after` alone, because HarnessTrim is the only integration it had been written against.

## OpenCode Desktop — inert

The same plugin, same global directory, driven through the real Desktop UI over the Electron remote
debugging port. Desktop ran the command unrewritten:

```
Shell git status --short
```

`total_commands` did not move. RTK's counter is the authority here, and it stayed flat.

The cause is in the plugin input. A probe logging `Object.keys(input)` and `typeof input.$` reports:

| Host | `keys` | `typeof input.$` |
| --- | --- | --- |
| OpenCode CLI 1.18.11 | `client, project, worktree, directory, experimental_workspace, serverUrl, $` | `function` |
| OpenCode Desktop 1.18.14 | `client, project, worktree, directory, experimental_workspace, serverUrl, $` | `undefined` |

The `$` key is present in both; only Desktop leaves it undefined. RTK's plugin opens with

```ts
try { await $`which rtk`.quiet() } catch { return {} }
```

so under Desktop the guard throws `TypeError: $ is not a function`, the catch returns an empty hook
set, and the plugin disables itself silently. It is not a PATH problem: `rtk.exe` resolves from the
persisted machine PATH (`AppData\Local\Microsoft\WinGet\Links`) that an Explorer-launched app
inherits. `which.exe` is *not* on that PATH, which would independently break the same guard, but the
missing `$` is what fires first.

This is an upstream defect in one of the two projects, not a Token Harness limitation, and it is a
property of the Desktop host rather than of any configuration Token Harness could write. It is
recorded as a platform limitation because a user who installs RTK for OpenCode and then works in
Desktop gets silence, not an error.

## What this changed

- `providers/rtk.ts` — OpenCode added to both shell capabilities at
  `tool.execute/tool-execute-before`, and to the harness compatibility list. Tested range raised to
  0.44.0.
- `harnesses/opencode.ts` — `tool-execute-before` declared, and the auto-loaded plugin directories
  are now read, so a plugin installed as a file is detected rather than missed.

No compatibility row was added. `COMPATIBILITY_ROWS` stays empty, so managed mutation remains
refused; this spike is detection and declaration evidence, not the reviewed cross-platform fixture
RFC 0009 requires.
