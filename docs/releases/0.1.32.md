# Token Harness 0.1.32 — Latest RTK releases

`0.1.32` lets Token Harness update RTK to its newest stable release, including the RTK 1.x line.
Earlier builds offered at most RTK 0.51.0, and WinGet still lists only v0.50.0.

## Installation

Download the matching asset from the [0.1.32 release](https://github.com/giuliastro/token-harness/releases/tag/v0.1.32):

- Windows x64: install the setup EXE and open Token Harness.
- Linux x64: install the DEB or extract the TAR.GZ into a permanent directory and
  run `token-harness-desktop`.
- macOS Intel or Apple Silicon: open the matching DMG/ZIP and copy the application
  into Applications.

For the CLI:

```sh
npm install --global token-harness@0.1.32
token-harness --version
token-harness
```

The version must be `0.1.32`. Restart an already running application to load the
updated interface.

## What changed

- **Latest-forward RTK updates.** The update check reads GitHub's newest stable `rtk-ai/rtk`
  release and accepts only `vX.Y.Z` tags, never the daily `dev-*-rc.*` prereleases. It offers
  that release, never less than the reviewed version. When GitHub cannot be read, the reviewed
  version remains the target and the check says so. No release request is made when no RTK
  executable can be replaced.
- **RTK 1.0.1 is the reviewed version.** Its official Windows release was exercised against
  every contract Token Harness consumes: `rtk --version`, the `rtk hook claude` and
  `rtk hook codex` JSON, `RTK_DB_PATH` and the history columns used for metrics. RTK 1.0.1 no
  longer reports an `unknown-newer` warning.
- The verified replacement path is unchanged: GitHub's published SHA-256, bounded extraction of
  the single root executable, post-install version check and automatic rollback.

To update RTK from the CLI:

```sh
token-harness update --provider rtk        # review the proposed version
token-harness update --provider rtk --yes  # apply it
```

RTK 1.0's default binary includes `rtk-engine` under BSL-1.1 (free production use; Apache-2.0
from 2030-09-09). Token Harness keeps selecting the default `rtk-*` asset distributed by WinGet
and the upstream installer. See [provider version compatibility](../provider-version-compatibility.md).

## Verification scope

[#387](https://github.com/giuliastro/token-harness/pull/387) passed native Windows, macOS and
Linux CI and all four desktop package targets. New tests cover latest-release selection, the
reviewed floor, offline fallback, prerelease rejection and the no-network case.

The RTK 1.0.1 check is a contract check on Windows, not a new harness-mutation compatibility row
or a combined-stack recording. Earlier runtime observations keep their original versions and
scope. This release makes no new token, subscription-quota or API savings claim.
