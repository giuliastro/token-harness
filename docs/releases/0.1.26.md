# Token Harness 0.1.26 — Automatic routing and dashboard repairs

`0.1.26` fixes routing plans rolled back during verification, Windows Claude npm-shim launches,
and native authorization reporting. It adds mcptoon installation through an existing uv and
consolidates dashboard controls and measured evidence.

## Installation

```sh
npm install --global token-harness@0.1.26
token-harness --version
token-harness
```

The version must be `0.1.26`. These commands also work in PowerShell.

## Automatic routing verification

1. Choose **Enable routing** or **Repair routing**, review the plan and apply it. Existing unrelated
   hooks must remain intact. Stored-plan installation must complete without repeating the harness
   selector on apply.
2. In Codex, open `/hooks`, enable and trust the three Token Harness routing definitions once:
   `UserPromptSubmit`, `SubagentStart`, `SubagentStop`. Token Harness does not grant this trust.
   In Claude Code, ensure hooks are enabled in `/hooks`.
3. Start a new agent session and submit an ordinary prompt. The dashboard must observe its callback
   automatically, without invoking a skill or using a command prefix.
4. Start another session in another project and submit a prompt. Overview counts span projects;
   benchmark evidence remains project-scoped. Subagent counters appear only for observed native
   events. A prompt callback alone implies neither a subagent launch nor routing savings.
5. If removal is desired, review and apply **Disable routing**. Only owned entries are removed;
   the transaction supports rollback.

Windows Claude uses shell form rather than exec-form `args` to launch npm `.cmd` shims. Owned legacy
entries can be repaired; modified or external hooks require review.

## Dashboard and maintenance verification

- Optimizer setup, connection and owned removal controls appear in one list.
- Without pipx or uv, mcptoon exposes **Installation options**. With an existing manager it exposes
  the reviewed install path. Token Harness does not bootstrap Python, pipx or uv.
- Results shows a dashboard followed by one list. Check text/type filters, sorting and expansion;
  exact and estimated measurements and their units must remain distinct.
- Recent activity stays bounded and scrollable.
- Startup checks notify about updates. Approved updates automatically re-check health. After
  updating Token Harness, **Restart and re-check** loads the replacement UI; failed startup retains
  the current dashboard.

Configuration and observed execution are separate verification tiers. Windows runtime claims
require actual Windows callbacks; fixtures and unit tests alone do not establish them.
