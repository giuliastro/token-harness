# Token Harness 0.1.24 — automatic native prompt routing

`0.1.24` adds an opt-in prompt policy for Codex and Claude Code. Enable it once in the guided app;
the native harness hook supplies the routing guidance on each submitted prompt. The skill does not
need to be invoked manually.

## Claude Code on Windows smoke test

After `0.1.24` is published:

1. In PowerShell, update and verify Token Harness:

   ```powershell
   npm install --global token-harness@0.1.24
   token-harness --version
   token-harness
   ```

2. On the Claude Code card, open **Automatic prompt routing**, review the plan, and apply **Enable**.
   Confirm the card reports the configured state. This is configuration evidence only.
3. Close the current Claude Code session and start a new one so it loads the updated user settings.
4. In a repository where changes are safe to review, submit a substantial task with one explicit,
   independent subtask, for example:

   > Inspect the existing test layout and identify one self-contained missing edge case. Use one
   > native subagent on the current Haiku model for that isolated analysis, then review its result
   > yourself. Do not edit files; report the test file and proposed assertion.

5. Refresh the Token Harness card. It should show **Runtime observed** and count a prompt callback;
   if Claude starts a child, it should also count a subagent start. A prompt callback proves the
   hook ran. It does not prove which model Claude actually selected. Claude's documented subagent
   callback does not include the child's model, so Token Harness leaves that field unknown unless a
   future stable runtime field is available.
6. To disable the feature, use **Disable routing** on the same card, review/apply the removal, and
   start a fresh Claude Code session.

## Savings evidence

The smoke test checks hook operation, not savings. **Results → Automatic routing** initially shows
**Not measured yet**. To measure savings, record matched baseline and routed benchmark tasks on the
same harness and task class, with comparable usage receipts and both quality gates passing. The UI
then reports exact local token deltas separately from authoritative five-hour and weekly allowance
percentages. No local count, model label, or subagent start is converted into an allowance saving.

Claude on Windows is considered runtime-verified only after the callback appears in the Token
Harness card on that machine. Codex still requires the user to review and trust its hook in `/hooks`.
