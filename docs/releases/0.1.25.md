# Token Harness 0.1.25 — Windows integration detection

`0.1.25` fixes Windows Codex hook inspection and RTK attribution detection. Guided integration
checks now distinguish a known failure from missing runtime evidence. Missing evidence does not
mean Claude Code is broken or must be configured.

## Windows smoke test

Run these steps in PowerShell on the Windows machine where Claude Code and Codex are installed:

1. Install the release and confirm the active command:

   ```powershell
   npm install --global token-harness@0.1.25
   token-harness --version
   token-harness
   ```

   The version command must print `0.1.25`. The last command opens the local dashboard.

2. Open **Activity → Check integrations**. Claude Code should be recognized as installed. If its
   settings are present but Token Harness has not observed a runtime callback, the result should
   say that runtime evidence is pending; it must not say Claude is absent or require Claude setup.
   This check does not change Claude settings.

3. On the Codex card, open **RTK → Review setup** (or the corresponding setup action), inspect the
   proposed per-agent tracking update, and apply it if the plan is valid for the existing RTK hook.
   Token Harness recognizes the Codex hook contract from RTK 0.50.0 and has a reviewed version range
   through 0.51.0. It should preserve existing Codex `commandWindows` hooks. Applying tracking routes
   RTK through Token Harness's attribution wrapper so RTK's shared history can be separated by agent.

4. In Codex, confirm any changed hook in `/hooks`, then run a shell command such as `git status`.
   Refresh the dashboard and re-check integrations. The Codex RTK row should show a recorded
   command once the wrapper callback and per-agent history are available. If no command has run
   through the hook yet, the result should remain an evidence-pending state with a specific reason.

5. To confirm Claude runtime monitoring, start a fresh Claude Code session, run a shell command
   through RTK, and refresh the dashboard. Claude settings are only changed if you separately
   review and apply a Claude setup plan.

These checks verify installation, configuration, and observed callbacks at separate tiers. They do
not prove that every shell command was reduced. Token Harness does not convert local RTK token
counts into five-hour or weekly allowance savings.
