# Token Harness 0.1.35 — Update status and acceptance protocols

`0.1.35` refreshes update notices after a verified provider update and makes the running application's installation source, version and path explicit. It also records desktop and paired-routing acceptance protocols. The protocols do not claim that their live evidence gates have passed.

## Installation

Download the matching desktop package from the [0.1.35 release](https://github.com/giuliastro/token-harness/releases/tag/v0.1.35). Windows x64 uses the setup EXE; Linux x64 uses the DEB or TAR.GZ; macOS Intel and Apple Silicon use the matching DMG or ZIP. Desktop updates use manual replacement of the published package.

For the CLI:

```sh
npm install --global token-harness@0.1.35
token-harness --version
```

The reported version must be `0.1.35`. Restart a running application to load the updated build.

## What changed

- After a reviewed RTK, HarnessTrim or other provider update, the dashboard clears its stale notice and rechecks available updates without a page reload. An application update that needs a restart shows a persistent restart action.
- Update status identifies the running copy's version, installation source and canonical package path. An `npx` dashboard does not imply the state of a separate global npm CLI.
- The desktop acceptance matrix records the installed-package checks needed on Windows, macOS and Linux. Its Linux 0.1.34 observations are partial and preserve the Hermes version-probe side effect for review.
- The paired-routing follow-up protocol requires repeated Codex and Claude Code trials, observed routing execution, independent quality checks and auditable raw receipts. Unknown values stay unknown.
