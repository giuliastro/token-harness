# Token Harness 0.1.9 — quota-aware optimization, guided local experience and outcome learning

`0.1.9` packages everything currently on `main` after `0.1.8`. It strengthens Token Harness as a practical efficiency layer around Claude Code and Codex: safer native policy handling, joint short/weekly budget awareness, a clearer guided local experience, and conservative learning from measured project outcomes.

## What changed

- **Claude and Codex compatibility is easier to diagnose.** Token Harness now explains compatibility and availability failures more clearly, observes supported native integration state without claiming execution it cannot prove, and keeps native-policy actions guarded.
- **Safe Claude effort policy.** Claude effort planning, apply, rollback and uninstall paths are handled conservatively, with ownership and compatibility checks preserved.
- **Stored-plan scope is preserved.** Applying a reviewed stored plan now restores the scope that was actually reviewed instead of silently widening it.
- **Guided local experience.** Setup, optimization state, rules and measured impact are surfaced through a more readable local app and guided flow.
- **Joint 5-hour and 7-day allowance policy.** The optimizer can reason about both short-window and weekly constraints together, protect reserves and task-quality floors, and reject stale or ambiguous quota evidence.
- **Outcome-aware effort learning.** Repeated quality-gated project outcomes can inform bounded native-effort choices while keeping explicit approval, catalog floors, plan identity and exact rollback safeguards.
- **Optimization history and impact reporting.** The CLI records and presents optimization history more clearly, with measured evidence kept distinct from estimates.
- **Clearer dashboard and progressive loading.** The dashboard communicates reasoning state more directly, loads progressively, and presents impact stories and shareable efficiency results without weakening the local privacy model.
- **Expanded regression coverage.** New unit and integration coverage exercises native policy, budget constraints, outcome learning, guided UI behavior, cross-harness evidence and release/distribution invariants.

## Upgrade

```sh
npm install --global token-harness@latest
```

Then run:

```sh
token-harness setup
token-harness ui
```

## Safety and behavior

Token Harness remains conservative by design. Unsupported or ambiguous native configurations are not silently changed, quota evidence must be trustworthy enough to influence planning, quality floors and reserves remain explicit, and learned policy changes stay bounded and reversible.

The local dashboard remains a local control/status surface rather than a cloud service; measured results are kept separate from modeled estimates so the tool does not present unverified savings as facts.
