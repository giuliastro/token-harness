# Token Harness 0.1.13 — Simpler first-run setup and actionable updates

`0.1.13` is a focused UX release built on top of `0.1.12`. The underlying optimizer lifecycle and safety model stay the same; the main change is that Token Harness now exposes that behavior through a much simpler first-run experience.

## What changed

- **Overview + Results.** The browser product now has two primary destinations instead of separate Dashboard/Setup/Results surfaces. Overview combines current state, first-run setup, optimizer health, updates and the measured-impact summary.
- **One first-run action per coding agent.** An incomplete Claude Code or Codex card exposes a single **Finish setup** action for the recommended RTK + HarnessTrim baseline. Duplicate baseline CTAs were removed from the overview status, detached setup boxes and individual RTK/HarnessTrim cards.
- **Actions live beside the state they resolve.** Installed optimizers that are not connected, integrations needing attention and reviewed updates expose the relevant action on the same card or maintenance row instead of in a separate action wall.
- **Optional optimizers stay optional.** mcptoon, GitNexus and Headroom remain independently reviewed optional integrations and are now collapsed by default behind progressive disclosure. They are not required to finish onboarding.
- **Advanced agent controls are secondary.** Allowance details, connected-tool observations and reasoning preferences are collapsed because they are not required for the normal setup path.
- **Reviewed updates are actionable.** **Check for updates** remains read-only. When a reviewed update is available, the same dialog can issue a short-lived approval ticket and expose **Install updates**. The apply path re-runs the existing update transaction safety checks before changing software.
- **Clearer CLI update confirmation.** The human `token-harness update` dry-run now retains the report needed to print the exact confirmation command: `token-harness update --yes`.
- **Safety model unchanged.** Configuration writes still require preview and explicit approval. Compatibility gates, ownership-aware removal, backups, rollback and refusal of unreviewed versions remain intact.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```

The browser app remains the primary human workflow. Open Token Harness, finish the recommended setup directly from an incomplete coding-agent card, and use **Results** when you want the detailed measurement evidence.

## Important boundaries

- **RTK + HarnessTrim remain the recommended production baseline.**
- **mcptoon, GitNexus and Headroom remain optional managed integrations.**
- **Managed configuration is not a savings claim.** Measured output, plan allowance, API cost and quality remain evidence-gated.
- **Updates remain reviewed and transactional.** A newer unreviewed provider version is not forced.
- **No compatibility or rollback semantics were widened in 0.1.13.**

`0.1.13` is an incremental stable release focused on making the existing safe behavior substantially easier to understand and operate.
