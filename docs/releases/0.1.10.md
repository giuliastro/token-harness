# Token Harness 0.1.10 — accepted-task capacity, quality-per-allowance and agent-native guidance

`0.1.10` packages the work merged after `0.1.9`. The main theme is turning raw provider limits into safer, quality-aware decisions: Token Harness now reasons about accepted-task capacity, model/reasoning/verbosity trade-offs, explicit remaining workload, mixed workloads and in-session guidance while keeping subscription quota, local token measurements and provider percentages separate.

## What changed

- **Accepted-task capacity.** Recent project-local successful receipts can estimate conservative remaining task equivalents from authoritative 5-hour and weekly allowance deltas. Estimates use exact policy identity where required and never convert local token counts into subscription quota.
- **Quality per allowance for reasoning, verbosity and model choice.** Lower-cost policies are selected only when measured outcomes preserve quality/retry gates and conservative backend allowance evidence supports the throughput claim. Higher-quality recovery remains possible when capacity allows it.
- **Workload-aware optimization.** When the user supplies the amount and shape of work left, Token Harness can spend allowance deliberately instead of treating every decision as an isolated task. Unknown workload remains unknown rather than guessed.
- **Mixed-workload allocation.** Explicit mechanical, standard, hard and critical backlogs can be distributed across supported harnesses while respecting quality floors, live capacity and the separate constraints of each provider.
- **Managed Codex model policy.** Model recommendations are guarded by native catalog/config evidence and the same review/apply protections used for other persistent policy changes.
- **Agent-native Token Harness skill.** Claude Code and Codex can consult Token Harness at meaningful task boundaries through the portable `skills/token-harness/SKILL.md` integration instead of requiring humans to memorize advanced CLI flags.
- **Guided Agent Skill installation.** The local app can preview and transactionally install the portable skill into the supported user-level Agent Skills directory after explicit approval.
- **Live guidance state.** Agent cards now distinguish Token Harness-managed guidance, identical external/user-owned guidance, absence, conflicts and unverifiable state. Matching bytes never silently create ownership, and rollback/uninstall cannot leave a ghost Enabled state.
- **Guided UI hardening.** Initial loading/layout behavior and rule presentation were tightened so the dashboard remains usable while observations arrive progressively.
- **Expanded regression coverage.** New unit/integration coverage exercises task capacity, quality-per-allowance, workload coverage, mixed-workload scheduling, managed model policy, Agent Skill behavior and the packaged installation path.

## Upgrade

```sh
npm install --global token-harness@latest
```

Then open Token Harness normally:

```sh
token-harness
```

Claude Code and Codex continue to be launched normally. In-session guidance is optional and can be enabled from the guided app after reviewing the proposed local change.

## Safety and measurement boundaries

Token Harness still does not compare raw Claude and Codex quota percentages as if they were a common currency. Provider allowance is normalized independently, local token/output measurements remain secondary evidence, and missing quota evidence does not become an invented estimate.

Persistent model, reasoning, verbosity or Agent Skill changes remain reviewable and reversible. Quality floors take precedence over throughput, and external/user-owned configuration is never silently adopted simply because it resembles Token Harness-managed content.
