# Token Harness 0.1.17 — real guided setup and Windows first-run fixes

`0.1.17` fixes the real-machine paths that were still failing in `0.1.16`, especially guided updates and optional optimizer setup on Windows.

## What changed

- **Approved guided updates now really install.** The browser read-only update check remains read-only, but `update --yes` now reaches the mutating transaction instead of being accidentally routed back through the check-only command.
- **HarnessTrim update is exercised end to end.** CI starts from the real public `harnesstrim@0.2.1`, configures Claude Code and Codex through the guided flow, discovers the newer release, approves it, installs it and verifies the executable that is actually active on PATH.
- **Optional optimizers are installable on Windows.** An absent mcptoon, GitNexus or Headroom is no longer reported as having “No compatible automatic setup surface” when Token Harness has a usable installer path.
- **Prerequisite failures are specific.** If the real blocker is a missing `pipx`, `npm` or `uv`, the guided UI says so instead of showing the generic compatibility message.
- **GitNexus first-run is managed.** Token Harness can install the reviewed GitNexus package through an existing npm and then register the reviewed Claude MCP entry.
- **Headroom has a verified uv tool channel.** Installation, inventory and rollback use `uv tool` without bootstrapping Python or uv itself.
- **Package rollback is stronger.** npm and uv inventory now distinguish an absent package from an unreadable result, allowing a first-run install to be reversed when the transaction later fails.
- **Managed setup must become real before commit.** After package/configuration actions finish, Token Harness re-observes the provider/harness integration. A setup that did not actually become active is rolled back rather than reported as completed.
- **Update failures contain better evidence.** When an installed target is not the executable that becomes active, diagnostics include package inventory and package-manager prefix information to make duplicate-PATH installs easier to find.

## Real-machine regression gates

This release is gated by the normal Windows/macOS/Linux suite plus real lifecycle smokes:

- Windows optional-provider first run with current Claude Code and GitNexus genuinely absent.
- HarnessTrim guided Claude + Codex setup followed by a real public-package update.
- Headroom MCP package contract through the uv channel on Windows, macOS and Linux.
- Existing RTK native Windows release smoke, bundle smoke and clean install smoke.

## Safety

Preview/approval, ownership checks, backup boundaries, drift detection, reversible package inventory and post-apply verification remain mandatory. Token Harness does not silently install system prerequisites or claim success from an installer exit code alone.

## Upgrade

npm install --global token-harness@latest
