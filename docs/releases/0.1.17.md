# Token Harness 0.1.17 — Real first-run setup and verified activation

`0.1.17` fixes the gap between “Token Harness knows about this optimizer” and “a normal user can actually install and connect it from the guided app”.

## What changed

- **Optional providers can now be installed from first run.** GitNexus uses an existing npm, mcptoon uses an existing pipx, and Headroom uses an existing uv tool installer. Token Harness still does not bootstrap Node, Python, pipx, uv or administrator prerequisites.
- **Missing prerequisites are named directly.** The guided UI no longer collapses an absent provider into the generic “No compatible automatic setup surface detected” when a reviewed setup path exists. When setup really cannot proceed, it says whether npm, pipx, uv or another prerequisite is missing.
- **Setup must become active before it can be reported as successful.** After the approved actions run, Token Harness re-detects the provider and requested coding agent. If the integration is not actually active, the transaction fails and rolls back.
- **npm and uv first-run installs are reversible.** Package inventory records the previous state and can restore an originally absent package instead of leaving a partial first-run behind.
- **HarnessTrim setup works against real user state.** Starting the guided app from HOME no longer trips repository-containment safety, and rollback snapshots cover the reviewed Claude/Codex surfaces instead of recursively copying unrelated history/cache.
- **HarnessTrim updates are exact and verified.** Approval is bound to the exact provider/version target, the active executable is re-read from PATH, and stale-path or failed-update cases cannot produce a green result.
- **Optimizer state is per agent.** A provider connected to another harness no longer makes Claude or Codex look connected when that specific agent still needs setup.
- **HarnessTrim 0.3.1 is reviewed.** Its managed-skill reinstall fix matches Token Harness’ transactional ownership model: an empty leftover skill directory is not treated as an installed skill, while an existing user skill with `SKILL.md` is preserved.

## Real release gates

The release path now exercises the user-visible flows with public packages instead of relying only on mocked adapters:

- Linux installs real `harnesstrim@0.2.1`, current public Claude Code and current public Codex in an isolated HOME, completes guided setup for both agents, updates HarnessTrim to registry latest, verifies the runtime resolved on PATH, removes one integration and reconnects it.
- Windows starts with GitNexus genuinely absent in isolated user/npm directories, requires the guided UI to expose a concrete install action, performs npm install + Claude MCP registration, re-detects the runtime and verifies the exact configuration.
- Headroom’s pinned uv tool/MCP contract is exercised on Ubuntu, macOS and Windows.

No model prompt, login, repository indexing or benchmark workload is required by these release gates.
