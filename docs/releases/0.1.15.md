# Token Harness 0.1.15 — Setup actions that actually resolve

`0.1.15` corrects the guided setup model after real-world testing exposed no-op **Finish setup** and **Connect to …** actions.

## What changed

- **No fake setup actions.** A setup button is rendered only when the detected provider can actually be assigned to that coding agent and the exact provider version, agent version, OS and WSL state have a reviewed compatibility admission.
- **RTK is no longer treated as a Codex integration.** The RTK adapter does not automatically configure Codex, so Token Harness no longer shows or plans RTK→Codex setup.
- **Setup incomplete now means actionable.** An agent is shown as **Setup incomplete** only when at least one reviewed automatic baseline change can actually be previewed and applied.
- **Unsupported combinations are explicit.** Installed providers that cannot be safely connected on the current version/platform show **no automatic setup** with an explanation instead of a useless Connect button.
- **Provider cards are data-driven.** The UI no longer hard-codes most providers as supporting both Claude and Codex.
- **State resolves after apply.** New stateful coverage verifies an actionable Codex + HarnessTrim setup transitions through preview/apply/re-observation to **connected**, with no actionable setup left afterward.
- **Stale setup actions self-correct.** If machine state changes between render and preview, the dashboard refreshes setup availability rather than leaving an obsolete CTA visible.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```

## Safety

No compatibility row was widened for this release. Unsupported combinations remain refused. The existing preview → approval → apply transaction path, ownership checks, backups, rollback and reviewed-version gates are unchanged.
