# Token Harness 0.1.14 — Actionable setup and automatic state refresh

`0.1.14` is a focused guided-UI correctness release on top of `0.1.13`. It fixes cases where the interface could report an incomplete setup without offering a usable way to complete it, and removes the need to manually refresh the page after Token Harness changes configuration.

## What changed

- **Finish setup now has a real path to completion.** Per-agent recommended setup explicitly plans the RTK and HarnessTrim integration changes for that coding agent instead of relying on a generic setup plan that could return no actionable change while the card still said **Setup incomplete**.
- **Installed but disconnected baseline optimizers are actionable.** RTK and HarnessTrim cards now expose a contextual setup/connect action for supported coding agents when the optimizer is installed but not connected.
- **Automatic refresh after approved changes.** After setup, update or removal is applied, the UI shows an in-progress refresh state, re-reads the current configuration, rerenders the dashboard and only then returns control to the user.
- **Manual refresh is now a fallback.** If the automatic re-read fails, Token Harness explains that the action completed but the latest state could not be loaded, and the ordinary Refresh action remains available to retry.
- **No duplicate dead-end notices.** When no safe managed change exists, the explanation is shown once rather than duplicated below the dialog.
- **Preserved capability paths behave consistently.** Secondary guided actions now follow the same apply → wait → refresh behavior instead of leaving the dashboard knowingly stale.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```

## Safety boundaries

- RTK + HarnessTrim remain the recommended production baseline.
- mcptoon, GitNexus and Headroom remain optional managed integrations.
- Setup still uses the existing preview → approval → apply transaction path.
- Compatibility gates, ownership checks, backups and rollback are unchanged.
- Unsupported or unreviewed versions are still not forced.
- No new savings, quality or compatibility claims are introduced by this release.

`0.1.14` is a patch release aimed at making the guided interface truthful: when Token Harness says setup is incomplete, it now offers an actionable safe path, and when it changes something, the UI refreshes itself before presenting the new state.
