# Token Harness 0.1.18 — attributed savings and safer updates

`0.1.18` brings agent- and harness-aware savings attribution, a Token Harness self-update path, and an evidence-bound Context Governor entry point.

## What changed

- **Savings can be attributed to the coding agent and harness.** Attribution uses inspected hook-command evidence, including the guarded RTK Codex hook proxy, instead of guessing from the app currently open.
- **Check for updates includes Token Harness.** For a verified global npm installation, the approved update installs the exact checked version, verifies the active version afterward and asks you to restart. Source and temporary copies are not self-updated through this path.
- **Context Governor starts from observed evidence.** The CLI accepts a read-only context snapshot and reports deterministic decisions and local byte counts without claiming token or quota savings.
- **Optional provider first-run paths have broader Windows coverage.** CI exercises the actual guided setup and verification paths for GitNexus, mcptoon, Headroom and HarnessTrim in isolated environments.

## Safety

Existing preview and approval flows, ownership checks, verification and rollback boundaries remain in place. Issue #255 remains open for before/after receipts from the complete production stack; this release is incremental and does not claim broad-promotion readiness.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```
