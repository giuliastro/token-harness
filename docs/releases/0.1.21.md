# Token Harness 0.1.21 — reliable Smart Model Routing and simpler controls

`0.1.21` is a corrective patch for the Smart Model Routing setup failure reported after 0.1.20. The routing workflow now preserves unrelated CCR changes, exposes its real active state in the guided browser, and reduces the normal interaction to Enable, Configure, or Disable on each coding-agent card.

## What changed

- **CCR changes are rebased instead of compared as one stale snapshot.** Token Harness now reads the latest CCR configuration immediately before an owned routing mutation and reapplies only its reviewed rule/profile changes on top of that state. Unrelated CCR metadata, provider configuration and external edits are preserved.
- **Routing state is explicit.** Each detected Claude Code or Codex card reports **Off**, **Shadow**, **Conservative**, or **Needs attention** from a read-only routing-status probe instead of inferring state from UI history.
- **Routing is integrated into the agent cards.** The detached Smart Model Routing section is gone. The primary controls are **Enable**, **Configure**, and **Disable** next to the affected coding agent.
- **First enable is one reviewed flow.** When the Token Harness-owned CCR runtime must be prepared, the browser completes runtime preparation and the selected routing configuration inside the same approved flow instead of asking the user to repeat setup.
- **Mode changes are simpler.** Switching Shadow ↔ Conservative replaces only the Token Harness-owned routing rule/profile after the same ownership checks.
- **Conservative mode has a real model selector.** The browser lists exact models already configured in CCR and requires one before Conservative routing can be enabled.
- **Activity is advanced evidence, not a primary setup action.** Local routing decisions remain inspectable without being presented as measured token, quota, or money savings.
- **CLI support matches the UI.** A read-only `--route-status` action and explicit `--route-simple-model <Provider/model>` option back the guided workflow.

## Safety

Token Harness still mutates only its exact owned CCR rule/profile/script state. Provider credentials and unrelated CCR settings are preserved, native Claude Code/Codex endpoints are not silently rewritten, and Conservative routing only uses an exact model already configured in CCR. Routing decisions remain separate from measured savings until attributable usage and quality evidence exists.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```
