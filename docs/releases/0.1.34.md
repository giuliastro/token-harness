# Token Harness 0.1.34 — Versioned read-only observe snapshot

`0.1.34` adds `token-harness observe --json`, one command that integrations can
poll for native quota windows, detected coding agents and the locally recorded
savings metrics, in a versioned JSON contract. It also ships the GitHub Pages
landing with direct author contacts.

## Installation

Download the matching asset from the [0.1.34 release](https://github.com/giuliastro/token-harness/releases/tag/v0.1.34):

- Windows x64: install the setup EXE and open Token Harness.
- Linux x64: install the DEB or extract the TAR.GZ into a permanent directory and
  run `token-harness-desktop`.
- macOS Intel or Apple Silicon: open the matching DMG/ZIP and copy the application
  into Applications.

For the CLI:

```sh
npm install --global token-harness@0.1.34
token-harness --version
```

The version must be `0.1.34`. Restart an already running application to load the
updated build.

## The observe command

```sh
token-harness observe --json --since 7d
```

One invocation returns the standard schema-1 CLI envelope
(`schemaVersion`, `command`, `toolVersion`, `status`, `exitCode`, `data`,
`diagnostics`) with a payload carrying its own contract version,
`data.contractVersion: 1`. Validate both versions and reject unknown ones
instead of guessing. The full contract is documented in
[observe-v1](https://github.com/giuliastro/token-harness/blob/main/docs/integrations/observe-v1.md)
with a [JSON Schema](https://github.com/giuliastro/token-harness/blob/main/docs/integrations/observe-v1.schema.json).

- `quotas` reports native harness quota windows with use percent, reset times,
  origin and confidence. `unavailable` or `absent` is unknown, never 0%.
- `agents[]` reports detected coding agents (`absent`, `detected`,
  `configured`, `broken`, `error`). Detection does not mean an active session.
- `metrics` aggregates only imported local evidence, scoped to all stored
  projects including unattributed records. It is not the current project's
  usage, and it can lag the provider's own records.
- `observedAt` is the observation instant of this CLI request; local event
  timestamps such as `firstRecordedAt` and `lastRecordedAt` are separate facts.

`observe` performs no Token Harness evidence writes: no provider imports, event
appends, import cursor changes, receipts, state-root initialization or
attribution changes. It may perform bounded native read-only quota probes. It
does not install software or change an agent configuration. A failed invocation
still returns the envelope with `data: null`; inspect `status`, `exitCode` and
`diagnostics`. Poll conservatively: one invocation can perform several native
observations.

## Metrics --read-only

Regular `token-harness metrics` preserves its existing behavior — it imports
each provider's records into the state directory before reporting. The new
`--read-only` flag reports from stored evidence without any import, cursor or
attribution writes, using the same non-importing path as `observe`. With no
usable pre-existing attribution salt it reports all stored projects rather than
synthesizing a project identity.

## Verification scope

[#386](https://github.com/giuliastro/token-harness/pull/386) passed the Windows,
macOS and Linux CI matrix including the desktop package checks, and local
review validation passed 2,590 tests with nine expected platform-conditional
skips plus typecheck, lint, formatting, the updated CLI goldens and bundle
smoke. The observe end-to-end read returns the versioned envelope with stored
metrics and native quota windows. Earlier releases' savings figures keep their
original scope, and this release adds no new savings claim: stored metrics are
delayed, all-project evidence and never establish subscription savings from
delegated activity or API pricing.
