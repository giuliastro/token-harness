# Token Harness 0.1.22 — remove unsupported CCR routing

`0.1.22` removes the CCR-based Smart Model Routing integration. It depended on a separate CLI
launch profile, while configuration checks could not prove that real Claude Code or Codex requests
were routed through CCR. Token Harness no longer installs or manages that router, exposes routing
controls, or reports CCR routing activity as benchmark telemetry.

## What changed

- Removed the managed CCR runtime and Smart Model Routing commands, guided controls, adapters, and
  routing-specific tests.
- Removed CCR routing fields and activity from the benchmark and capability surfaces.
- Made the Codex RTK activation step explicit: after setup, open Codex and manually enable and trust
  the hook. Token Harness cannot activate the hook or grant trust; a `hooks.json` declaration alone
  is only config evidence.

Existing provider credentials, native endpoints, and user-owned CCR state are left untouched.
This incremental release does not claim broad-promotion readiness.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```
