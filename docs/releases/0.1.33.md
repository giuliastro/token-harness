# Token Harness 0.1.33 — Desktop, interface first

Token Harness now brings its redesigned **Home, Methods and Details** interface
together with more complete desktop workflows. Install the app, choose your project
and use the guided controls to configure optimizers, understand their activity and
review changes before applying them. The CLI remains available for automation and
advanced workflows.

## Get the desktop app

Download the installer for your computer from this release:

- [Windows x64 setup](https://github.com/giuliastro/token-harness/releases/download/v0.1.33/token-harness-0.1.33-windows-x64-setup.exe)
- [macOS Apple Silicon DMG](https://github.com/giuliastro/token-harness/releases/download/v0.1.33/token-harness-0.1.33-macos-arm64.dmg)
- [macOS Intel DMG](https://github.com/giuliastro/token-harness/releases/download/v0.1.33/token-harness-0.1.33-macos-x64.dmg)
- [Linux x64 DEB](https://github.com/giuliastro/token-harness/releases/download/v0.1.33/token-harness-0.1.33-linux-amd64.deb)

macOS ZIP and Linux TAR.GZ packages are also attached, together with SHA-256 checksums.
Windows installers are unsigned; macOS packages use ad-hoc signing without Apple
notarization. Signing remains deferred. On macOS, copy the app into Applications;
the app now offers to do this before starting configuration work. Keep the installed
application in a stable location while agent integrations use its bundled runtime.

The CLI is available separately:

```sh
npm install --global token-harness@0.1.33
token-harness --version
```

Restart the app after upgrading. The interface and native **Help → About Token
Harness** show the software version, populated from the same release version used
for the CLI and desktop package. Future releases update these displays automatically.

## A clearer everyday interface

- **Home** presents setup status, measured output reduction, a daily activity chart,
  delegated token usage and current plan balances. Estimates and observed activity
  remain labelled separately from measured savings.
- **Methods** puts RTK, HarnessTrim and model routing alongside the other supported
  methods, with consistent setup, connection, removal and reviewed update controls.
- **First-run setup** reviews the recommended configuration before making changes.
  The app includes English and Italian, light and dark themes, and a loading screen
  during its first read.
- **Details** keeps evidence, diagnostics, change history, recovery and the advanced
  tools available without crowding the everyday view.

## More work from the interface

Open **Details → Advanced tools** to:

- Plan a workload with an explicit task, profile, reserve and optional task count.
- Compare coding agents against a mixed workload. Advice preserves unknown results
  when matched quality or allowance evidence is missing; it does not switch agents.
- Prepare and copy a compact handoff from the facts you enter, without model calls
  or automatic file reads.
- Review four-arm compression/routing experiments, prepare supported configurations,
  record manual outcomes, restore saved settings and read the comparison report.
  The app does not execute benchmark checks or reset your source tree.
- Review the owned optimizer/routing connections before removing the desktop app.
  Opening this checklist changes nothing; each change still requires review.

The desktop remembers the selected project, restores it on reopening and focuses
the existing window when launched again. Desktop update checks link to desktop
downloads. Updated CLI and app builds coordinate managed changes so two processes
cannot modify the same state at once; older CLI builds do not participate.

## Routing and measurements

Routing now delegates eligible bounded work more readily, while architecture,
security, releases, unclear debugging, integration and final review remain with the
main agent. Claude routing prefers the `haiku` alias for suitable work and advises an
update when an older Claude Code version resolves that alias to Haiku 4.5. Existing
compatibility admission checks still apply.

Read-only local transcript readers provide per-model main/subagent token counts;
transcript text is not sent to the UI. Metrics also include a daily series.
Delegated activity and API-price estimates do not establish subscription savings.

## Release automation and scope

Each release builds native Windows, Linux and macOS Intel/Apple Silicon packages.
New GitHub releases stay in draft until the expected CLI, seven desktop packages
and desktop checksum asset have been uploaded and verified. Desktop artifact
provenance is attested alongside the existing CLI provenance/SBOM. Versioned notes
from the repository are used automatically when available.

The release gates include cross-platform tests, packaged runtime/renderer smoke,
bundle and installed-package smoke, and existing isolated live setup/update checks.
These checks do not establish every native installer lifecycle, external agent
integration or a measured savings benefit. WSL remains a separate CLI environment.

Candidate campaign progression, transfer evaluation/receipts and executable
benchmark checks retain their advanced CLI workflows. The removal checklist does
not intercept OS uninstall or certify external connections. Issue
[#379](https://github.com/giuliastro/token-harness/issues/379) remains open for the
remaining desktop acceptance criteria.
