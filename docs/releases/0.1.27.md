# Token Harness 0.1.27 — Clearer Overview and Results

`0.1.27` makes setup actions easier to find and recorded benefits easier to inspect. Evidence now
uses a responsive expandable list with consistent filters and structured measurement details.

## Installation

```sh
npm install --global token-harness@0.1.27
token-harness --version
token-harness
```

The version must be `0.1.27`. These commands also work in PowerShell. Restart an already running
dashboard to load the updated interface.

## What changed

- Overview has shorter explanations, compact impact cards and direct actions for available setup
  or required attention.
- Evidence filters match the rest of the interface. Search includes provenance inside collapsed
  details, source counts update immediately, and **Clear filters** restores the complete list.
- **With results first** prioritizes recorded evidence. Expand a source to inspect each measurement
  class and unit separately, including before/after values, saved or added output, operation counts
  and the recorded coding app.
- App-linked results identify the optimizer records they reuse. Detected setup never supplies
  missing runtime attribution or creates additional savings.
- Routing separates hook verification and callback activity from paired, quality-gated savings.
- Keyboard navigation supports arrow keys, Home and End. Expanded details survive refresh; mobile
  connections use cards, and the appearance selector remains available on small screens.
- The release also includes the simplified onboarding and reconciled delivery roadmap merged since
  `0.1.26`.

## Verification scope

Interaction tests cover separate measurement classes/units, missing attribution, combined filters,
empty/reset states, sorting, retained disclosures, blocked claims, increased usage and keyboard
navigation. Visual checks cover desktop and 375px layouts in light and dark themes using synthetic
data. Release publication additionally requires cross-platform CI and exact-artifact smoke checks.

These checks establish UI behavior and package integrity. They do not establish additional provider
compatibility, native Windows callback execution or new token, subscription or API savings.
