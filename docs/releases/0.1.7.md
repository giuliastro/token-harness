# Token Harness 0.1.7 — simpler onboarding and Windows coverage

`0.1.7` makes the npm package match the new beginner-first README and closes the Windows gaps found during a real first run.

## What changed

- **One-command onboarding.** `token-harness setup` is now the primary first-run command. It summarizes what was detected, what already works, what would change, and one useful next step.
- **Local dashboard.** `token-harness ui` opens the small loopback-only dashboard introduced with the simplified onboarding flow.
- **Claude Code PowerShell coverage on Windows.** Token Harness can add the missing `PowerShell` matcher alongside `Bash` while using the same native `rtk hook claude` processor.
- **Live compatibility evidence.** Claude Code 2.1.251 was exercised on a real Windows runner with RTK 0.44.0 and 0.48.0, including apply, direct PowerShell rewriting, user drift, rollback, and surgical uninstall.
- **Current RTK recognition.** RTK 0.48.0 is within the observed provider range, so updating to current RTK no longer immediately produces a false newer-than-tested warning.
- **Cleaner companion onboarding.** `doctor` surfaces `token-harness update` so old user-owned RTK or HarnessTrim installations are discoverable without silently replacing them.
- **Optional integrations stay optional.** Pi without the optional HarnessTrim extension is no longer reported as a failed integration.
- **Safer rollback.** When several actions touch the same file in one transaction, rollback restores the original pre-transaction snapshot instead of an intermediate state.
- **Claude quota companion alignment.** The Windows companion documentation reflects cclimits 1.7.0 and its merged zero-config Claude sources.

## Recommended first run

```sh
npm install --global token-harness@latest
token-harness setup
```

Then open the dashboard with:

```sh
token-harness ui
```

If `setup` proposes a supported configuration improvement, review it and use `token-harness setup --yes` explicitly. Unsupported or unrecorded combinations remain untouched.

## Windows notes

The detailed Windows companion path is documented in [`docs/windows-companions.md`](../windows-companions.md). RTK PowerShell management is intentionally Windows-scoped: the portable RTK capability remains Bash, while the planner adds PowerShell only when Claude Code exposes that Windows tool family.

## Why this release matters

The README now tells new users to install `token-harness@latest` and start with `setup`. Publishing 0.1.7 makes that path real: the npm `latest` package contains the simplified onboarding/dashboard work as well as the Windows fixes and evidence added after 0.1.6.
