# Token Harness 0.1.23 — Codex runtime verification

`0.1.23` improves verification for users running Codex Desktop without the optional Codex CLI on
their shell `PATH`, while keeping configuration evidence separate from runtime proof.

## What changed

- A missing `codex` executable no longer marks an otherwise detected Codex Desktop integration as
  broken. CLI-only checks are reported as unobserved.
- Codex hook declarations and native enablement/trust remain config/state checks. They do not claim
  that a hook ran.
- RTK and HarnessTrim report separate, harness-attributed canary receipts. RTK command history and
  HarnessTrim reduction telemetry can prove their own runtime interceptions even when Codex's
  optional event-stream CLI is unavailable.
- HarnessTrim uninstall removes its exact managed hook on Codex or Claude while preserving other
  user hook entries in the same config file.
- `verify --harness codex` scopes provider rows to Codex, and the compatibility fixture covers the
  reviewed RTK + HarnessTrim chain on Linux.

The release does not claim exact model-token savings from character-reduction telemetry and does not
claim broad-promotion readiness.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness verify --harness codex
```
