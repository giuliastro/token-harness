# Token Harness 0.1.12 — Optional managed optimizers, exact-row evidence and safer campaigns

`0.1.12` packages the work merged after `0.1.11`. The headline change is that **mcptoon 0.7.10, GitNexus 1.6.12 and Headroom 0.37.0 now participate in Token Harness' ordinary optional managed-provider lifecycle** while **RTK + HarnessTrim remain the production baseline**.

The release also includes the GitNexus and mcptoon evidence hardening that made that lifecycle safe to expose: exact-version admission, compatibility/reversibility rows, campaign provenance, contamination checks, activation-evidence boundaries and a quota-conscious real-campaign path.

## What changed

- **Unified Optimization Stack.** The guided Setup view now presents RTK, HarnessTrim and the reviewed optional managed integrations in one managed-optimizer surface. The RTK + HarnessTrim baseline remains distinct; optional providers are reviewed one at a time and do not become a savings or compatibility claim just because setup is available.
- **mcptoon 0.7.10 as an optional managed integration.** Exact reviewed Claude/Codex guidance can be installed and removed transactionally. Token Harness may use an already-installed `pipx`, but it never bootstraps Python, pipx or administrator prerequisites. Exact candidate evidence remains fail-closed outside reviewed rows.
- **GitNexus 1.6.12 as an optional managed Claude integration.** Token Harness can own only the exact reviewed Claude MCP registration and remove it surgically. It does **not** install GitNexus, create or refresh repository indexes, or infer commercial-use permission; the PolyForm Noncommercial licensing boundary remains visible.
- **Headroom 0.37.0 managed MCP registration.** Token Harness can own the reviewed local `headroom mcp serve` registration for Claude Code and Codex on exact config-only rows. The Headroom package remains a user-owned prerequisite. Token Harness does not bootstrap Python/uv and does not run Headroom wrap, proxy or deploy workflows.
- **Exact Headroom compatibility smoke.** CI verifies the pinned Headroom package/CLI contract on Ubuntu, macOS and Windows and checks that the reviewed Claude Code and Codex configurations are parsed by the real harness CLIs without a model prompt, login, API request or benchmark.
- **GitNexus campaign hardening.** Candidate evidence now fails closed on unsupported versions, contaminated baselines, missing version provenance, unavailable index state and unreviewed platform/harness rows. MCP availability and actual GitNexus tool use remain separate evidence.
- **Quota-conscious real GitNexus campaign tooling.** The real campaign is explicit/manual-only, defaults to a frugal Claude configuration, keeps ordinary CI model-free and requires a real GitNexus tool-use witness before optimized evidence can be credited.
- **mcptoon exact-row evidence.** The release includes the reviewed Codex 0.153.0 × mcptoon 0.7.10 Linux row and the bounded campaign/evidence path added after 0.1.11. Historical mixed campaign results remain evidence, not a savings claim.
- **Windows production-stack evidence collector.** A native-Windows collector and runbook can capture the RTK + HarnessTrim production-stack evidence needed for separate combined-stack review. Its synthetic CI self-test does not pretend to be real workload evidence.
- **Release safety gates remain strict.** Normal CI still covers typecheck, lint, format, full tests, GitNexus runner self-test, Windows RTK live release replacement, build, bundle smoke, package staging and install smoke on all supported CI platforms.

## Upgrade

```sh
npm install --global token-harness@latest
token-harness
```

The browser app remains the primary human workflow. Claude Code and Codex are launched normally; Token Harness manages only reviewed surfaces and requires explicit preview/approval before configuration writes.

## Important boundaries

- **RTK + HarnessTrim remain the production baseline.** mcptoon, GitNexus and Headroom are optional managed integrations, not an automatic recommended combined stack.
- **Managed lifecycle is not measured value.** Configuration ownership does not imply token, quota, cost or quality savings.
- **GitNexus is not auto-installed or auto-indexed.** Its reviewed license boundary is intentionally visible.
- **Headroom package ownership stays external.** Token Harness manages the narrow MCP registration, not Python/uv/package installation or wrapper/proxy/deploy execution.
- **Candidate evidence stays conservative.** Detection, configuration, MCP availability and benchmark attribution are kept separate from verified runtime use and promotion decisions.

`0.1.12` is an incremental stable release. Broader production-stack promotion remains gated by independent combined-stack and real-workload evidence.
