This release fixes the guided first-run path on real machines rather than merely changing UI copy. Optional managed providers are now actionable when Token Harness has a reviewed installer path: GitNexus can be installed through an existing npm, mcptoon through an existing pipx, and Headroom through an existing uv. When a prerequisite is actually missing, the guided UI names that prerequisite instead of reporting the generic “No compatible automatic setup surface detected”.

Managed setup is now verified before the transaction commits. After install/configure, Token Harness re-observes the provider and requested coding agent; if the integration did not actually become active, the transaction fails and restores the captured state instead of reporting a false success. The npm and uv first-run paths have machine-readable package inventory and absence rollback support.

HarnessTrim guided setup/update is also hardened against real user state: HOME is no longer misclassified as a repository for backup containment, rollback snapshots are narrowed to the reviewed Claude/Codex surfaces instead of whole state trees, optimizer state is per coding agent, approved updates are bound to the exact provider/version target, and the active executable is re-read from PATH after mutation. HarnessTrim runtime artifact digests are consumed from 0.2.0 onward.

Release-blocking evidence now includes a live Linux guided gate that starts from real `harnesstrim@0.2.1`, current public Claude Code and Codex, completes setup for both agents, updates HarnessTrim to registry latest, verifies the active PATH runtime, uninstalls one integration and reconnects it. Windows CI includes a real isolated first-run gate where GitNexus begins absent and the guided path must install it, register Claude MCP, re-detect the active runtime and verify the resulting configuration. Headroom’s reviewed uv tool contract is exercised on Ubuntu, macOS and Windows.

HarnessTrim 0.3.1 was reviewed against 0.3.0 before advancing the historical provider baseline. It fixes exactly the transactional reinstallation case Token Harness needs: leftover empty skill directories no longer suppress restoration of owned `SKILL.md` files, while same-named user skills containing `SKILL.md` remain non-overwritten. Reducers, model choice, reasoning effort, telemetry semantics and published skill contents are unchanged.
